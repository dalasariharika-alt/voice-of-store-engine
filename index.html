1. Project Objective

Develop an intelligent application that collects retail employee feedback, analyzes it using AI, identifies recurring problems, and helps managers take corrective action.

Core mission: Convert unstructured employee feedback into meaningful insights and track the corrective actions taken to resolve workplace issues.

2. Technology Stack

Frontend React, TypeScript, Vite, Tailwind CSS, and Recharts.
Backend Python, FastAPI, and REST APIs.
AI/ML Python NLP, sentiment analysis, text classification, keyword extraction, urgency detection, and similarity-based clustering.
Database SQLite with persistent storage.

3. Core Features

3.1 Interactive Dashboard

  • Display real-time feedback statistics.
  • Visualize sentiment analysis and issue categories.
  • Highlight urgent concerns and recurring problems.
  • Display corrective-action status using interactive charts.

3.2 Feedback Submission

  • Allow employees to submit feedback.
  • Capture store, department, category, and urgency details.
  • Include optional voice-to-text functionality.

3.3 AI Analysis

Analyze every feedback submission and provide:

  • Sentiment classification.
  • Predicted feedback category.
  • Important keywords.
  • Urgency recommendations.
  • A concise explanation of the analysis.
  • Suggested solutions and corrective measures.

3.4 Feedback Explorer

  • Search feedback records.
  • Filter and sort feedback by relevant fields.
  • View feedback alongside its AI analysis.

3.5 Recurring Issue Detection

  • Group similar feedback submissions.
  • Identify repeated workplace problems.
  • Detect issues such as stock shortages, billing failures, staffing shortages, and customer complaints.

3.6 Manager Action Center

  • Create corrective actions.
  • Assign actions to responsible personnel.
  • Set priorities and deadlines.
  • Update action statuses.
  • Add notes and track resolution history.
  • Resolve actions and monitor outstanding issues.

3.7 Reports and Export

  • Generate reports from stored feedback data.
  • Export filtered, actual database records to CSV.

3.8 AI Transparency

  • Explain how the AI analysis works.
  • Document AI limitations.
  • Identify whether an analysis uses a machine-learning model or a rule-based fallback.

3.9 User Roles and Permissions

  • Provide separate employee and manager access.
  • Enforce role-based permissions on the backend.
  • Protect manager-only operations from unauthorized access.

3.10 Demo Data

  • Include realistic fictional feedback records.
  • Allow judges to explore the application immediately.

4. UI/UX Requirements

Create a premium, modern enterprise SaaS interface with a sophisticated navy, white, and teal/blue color palette.

  • Professional typography.
  • A clean, intuitive sidebar.
  • Elegant dashboard cards.
  • Interactive charts.
  • Consistent spacing and visual hierarchy.
  • Subtle animations and polished transitions.
  • Responsive desktop and mobile layouts.
  • Working navigation and primary controls.
  • Loading indicators and validation messages.
  • Graceful error handling and useful empty states.

5. Development Requirements

  1. Build the actual application in the current workspace, not just a frontend mockup.
  2. Organize the code into maintainable frontend, backend, database, and AI modules.
  3. Connect every page to working API endpoints.
  4. Persist feedback, AI analysis, recurring themes, and corrective actions in SQLite.
  5. Implement genuine NLP processing using an appropriate local model when feasible.
  6. If a model or external service is unavailable, provide a transparent, functional local fallback.
  7. Do not require paid APIs for core features.
  8. Include automated backend tests.
  9. Include a .env.example file if needed.
  10. Provide a clear README with installation instructions, startup commands, demo login details, and troubleshooting guidance.
  11. Validate user input and handle errors gracefully.
  12. Protect manager-only operations on the backend.
  13. Avoid exposing sensitive employee information.
Data integrity requirement: Use actual database calculations for dashboard metrics. Never fabricate AI results, statistics, records, or successful operations.

6. Execution Instructions

Begin building the complete application and continue through implementation and verification without stopping after creating a plan.

  1. Inspect the workspace: Examine existing files and project configuration before making changes.
  2. Plan the architecture: Define the frontend, backend, database, and AI module structure.
  3. Implement the application: Build the database, backend APIs, AI processing pipeline, and frontend.
  4. Integrate all features: Ensure the pages, endpoints, database, and AI processing exchange data correctly.
  5. Run and test: Start the frontend and backend, execute available tests, verify the production build, and fix errors.
  6. Test the complete workflow: Verify feedback submission, AI analysis, dashboard updates, recurring issue detection, corrective-action creation and updates, and export of real data.
  7. Verify the interface: Test all primary buttons, navigation items, forms, filters, and charts.

Complete Workflow to Verify

Employee submits feedback → AI analyzes the submission → dashboard metrics update → recurring issues are identified → manager creates a corrective action → action status is updated → actual database records are exported.

Final Deliverables

  • Complete, runnable full-stack application.
  • React and TypeScript frontend.
  • FastAPI backend with REST endpoints.
  • SQLite database with persistent records.
  • AI/NLP processing modules with transparent fallback behavior.
  • Automated backend tests.
  • README and environment configuration example.
  • Exact startup commands.
  • Demo credentials.
  • Implemented features and test results.
  • Documentation of any remaining limitations.
Final instruction: Prioritize functionality, reliability, professional design, and a smooth competition demonstration. Do not claim that any feature or test works unless it has been verified. If any limitation remains, document it honestly.
